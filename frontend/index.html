How it works

A complaint travels a fully automated path from the citizen's phone to a verified resolution.

1

Citizen submits a complaint

Title, description, priority, and a GPS pin on the map. Optional photos up to 3.

2

AI classifies & detects the ward

The system detects which ward the location falls in and AI classifies category, priority, and department.

3

Auto-assigned to a worker

The complaint is assigned to the available worker with the lowest workload in that ward.

4

Worker resolves & uploads proof

The worker accepts, works, and uploads progress and completion photos.

5

Area admin verifies & closes

Completed work is verified, then the complaint is closed and the citizen is notified.

Powered by a modern stack

Built with reliable, open technologies that scale from a single ward to an entire state.

Frontend

HTML5, CSS3, and Vanilla JS with the DM Serif Display + DM Sans type system and dark/light themes.

Backend

Node.js + Express 5 (ES Modules) exposing 55+ REST endpoints with layered services and route guards.

Database

PostgreSQL via Supabase with PostGIS for real-time ward detection from GPS coordinates.

AI Engine

Groq API (LLaMA 3) classifies category, priority, and department for every complaint in real time.

Auth & Security

JWT access + refresh tokens, OTP email verification, invite links, and role-based route protection.

Media & Maps

Cloudinary for complaint images and Leaflet + OpenStreetMap for interactive location picking.

Email

Brevo (Sendinblue) powers invitations, OTPs, and complaint status notifications to every user.

Notifications

In-app notification center with unread badges, filters, and priority levels for every event.
